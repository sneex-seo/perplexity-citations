# perplexity-citations

Показує, які сайти Perplexity бере за джерела, коли відповідає на ваші промпти, і де з цього отримати посилання.

Даєте список запитів, скрипт проганяє їх через Perplexity API і для кожної відповіді зберігає:
- усі сторінки, які знайшов пошук;
- ті з них, на які відповідь справді посилається, і в якому порядку;
- зведення по доменах: хто цитується найчастіше і в скількох відповідях.

Звіт починається з того, що перевіряли: бренд, сайт, конкуренти, країна пошуку і всі запити. Далі - порівняння вашого бренду з конкурентами: скільки разів Perplexity називає кожен бренд у відповідях і як часто його сайт серед джерел.

Головне для лінкбілдингу - список «Де отримати посилання»: кожен процитований домен із типом (медіа, блог, форум, маркетплейс, магазин, вікі, держсайт), що з ним робити і пріоритетом. Якщо вказати свій домен і бренд, скрипт відкриє процитовані сторінки і покаже, де вас уже згадують без посилання.

Для чого це:
- **Лінкбілдинг і PR.** Список донорів, відсортований за тим, як часто AI бере їх за джерело у вашій ніші.
- **Швидкі виграші.** Сторінки, які вже згадують ваш бренд без посилання: досить попросити його додати.
- **GEO і контент.** Видно, чи є ваш сайт серед джерел, і які запити закривають інші сайти.

Приклад звіту на 30 запитів: https://oleksiimatuznyi.com/lab/perplexity-citations/

## Запуск

Потрібен Python 3.10+ і ключ Perplexity API. Ключ створюється в консолі https://console.perplexity.ai/project/keys, оплата за фактом використання.

```bash
git clone https://github.com/sneex-seo/perplexity-citations.git
cd perplexity-citations
pip install -r requirements.txt
cp .env.example .env          # Windows: copy .env.example .env
python citations.py prompts.example.txt
```

Ключ впишіть у `.env` у рядок `PERPLEXITY_API_KEY=`. Файл `.env` не потрапляє в git.

Свої промпти покладіть у txt, по одному на рядок, або в першу колонку xlsx чи csv. Для свого проєкту:

```bash
python citations.py prompts.txt --domain example.com.ua --brand "Example,Ексампл" \n    --competitors "Rival,Other=other.com.ua,shop.ua" --exclude-tld ru,by
```

## Параметри

| Параметр | Що робить |
|---|---|
| `--domain` | Ваш домен. Для кожного запиту видно статус: процитовано, знайдено, але не процитовано, або немає серед джерел. На сторінках-кандидатах шукаються посилання на нього. Піддомени рахуються як ваші. |
| `--brand` | Назви бренду через кому. Скрипт рахує, у скількох відповідях Perplexity називає бренд, і шукає назви в основному тексті процитованих сторінок: так знаходяться згадки без посилання. |
| `--competitors` | Конкуренти через кому: назва бренду (`Rival`), назва з доменом (`Other=other.com.ua`) або лише домен. Без параметра конкурентами вважаються п'ять магазинів, які Perplexity цитує найчастіше. |
| `--effort` | Режим Perplexity Agent API: `fast` (за замовчуванням), `low`, `medium`, `high`. Див. «Який режим обрати». |
| `--country` | Код країни, з якої шукати. За замовчуванням `UA`, порожній рядок прибирає прив'язку. |
| `--exclude-tld` | Не показувати у звітах джерела з цих доменних зон, через кому, наприклад `ru,by`. Звіт пише, скільки джерел приховано, журнал лишається повним. |
| `--domain-filter` | Шукати лише на цих доменах, через кому. Домен із мінусом виключається. |
| `--recency` | Лише свіжі джерела: `day`, `week`, `month`, `year`. |
| `--no-fetch` | Не відкривати процитовані сторінки. Тип сайту визначається лише за адресою, згадки бренду не шукаються. |
| `--limit` | Лише перші N промптів, для перевірки. |
| `--out-dir` | Куди писати журнал і звіти, за замовчуванням `results`. |
| `--fresh` | Прогнати промпти заново, а не брати відповіді з журналу. |
| `--report-only` | Перебудувати звіти з журналу без запитів до API, наприклад з іншим `--brand`. |

## Що виходить

У папці `results`:
- `report.html` - звіт: що перевіряли і які запити, ваш бренд і конкуренти, «Де отримати посилання», таблиця доменів, кожна відповідь із пронумерованими джерелами;
- `citations_YYYY-MM-DD.xlsx` - аркуші «Що перевіряли», «Конкуренти», «Де отримати посилання», «Відповіді», «Джерела», «Домени», а з `--domain` ще «Ваш домен»;
- `journal.jsonl` - журнал відповідей. Перерваний прогін можна запустити знову: готові промпти не повторюються і не оплачуються вдруге;
- `pages.json` - кеш відкритих сторінок.

Процитованими вважаються джерела, на які відповідь посилається маркерами `[1]` або `[web:1]`. У звіті номери в тексті відповіді збігаються з номерами в списку джерел: [1] - перше джерело, на яке послалася відповідь. Решта знайдених сторінок теж є у звіті з позначкою «не процитовано». Формули, які Perplexity пише у форматі LaTeX, звіт показує звичайним текстом.

## Ваш бренд і конкуренти

- **Названо у відповідях** - у скількох відповідях Perplexity згадує бренд у тексті. Це видимість бренду в AI-відповідях, навіть коли його сайт не серед джерел.
- **Сайт у джерелах** - у скількох відповідях сайт бренду серед процитованих джерел.

Ваш рядок стоїть першим, далі конкуренти від найпомітніших. Біля кожного - запити, у яких його назвали або процитували.

## Де отримати посилання

Для кожного процитованого домену скрипт відкриває його сторінки, які цитує Perplexity, і визначає тип: за списками відомих сайтів, адресою, розміткою schema.org (NewsArticle, BlogPosting, Product) і ознаками кошика.

| Тип | Що робити | Вага |
|---|---|---|
| медіа | PR: експертний коментар, новина або колонка з посиланням | 1 |
| блог / огляд | Аутріч: гостьова стаття або місце в огляді чи добірці | 1 |
| форум / соцмережа / відео | Відповідь у темі, огляд або відео | 0.8 |
| маркетплейс / агрегатор | Картка товару або лістинг: присутність серед джерел, а не посилання | 0.6 |
| інше | Перевірити вручну | 0.5 |
| магазин | Для бренду - партнерство, для магазину - конкурент, чию сторінку варто вивчити | 0.4 |
| вікі | Правка з посиланням на першоджерело за правилами вікі | 0.3 |
| держ. / освіта / наука | Донором не стане, але на нього варто посилатися у своєму контенті | 0.1 |

Пріоритет - у скількох відповідях процитовано домен, помножене на вагу типу. Якщо сторінки вже згадують ваш бренд без посилання, пріоритет ×1.5, якщо вже посилаються на вас - ×0.3.

Згадки бренду шукаються лише в тексті статті: в `articleBody` з розмітки або в `article` і `main` без меню, каталогу, блоків товарів, «читайте також» і посилань поза абзацами. Біля кожного статусу «згадує бренд без посилання» звіт показує цитату і сторінку, де стоїть згадка.

Тип визначається евристиками, тому список варто переглянути очима. Сторінки відкриваються з User-Agent `perplexity-citations` і з повагою до robots.txt. Якщо сайт закритий від ботів, тип визначається за адресою, а статус бренду - «не вдалося перевірити».

## Який режим обрати

Замір 12.11.2026 на трьох запитах із прикладу, пошук з України:

| Режим | Знайдено сторінок | Процитовано | Ціна запиту | Час |
|---|---|---|---|---|
| `fast` | 10 | 3-5 | $0.002 | 3-5 с |
| `low` | 15-30 | 3-4 | $0.002-0.005 | 10-25 с |
| `high` | 45-105 | 2-7 | $0.02-0.06 | 20-50 с |

- Глибші режими знаходять у рази більше сторінок, але цитують не більше.
- Процитовані домени в різних режимах майже не збігаються: на кожному запиті спільних 0-1 домен. Порівнювати прогони варто лише в одному режимі.
- Повторний прогін у `fast` через годину знайшов ті самі 8-10 сторінок із 10, а процитував від 1 з 6 до 5 з 6 тих самих доменів.

За замовчуванням стоїть `fast`: дешево, швидко і стабільно. `high` має сенс, якщо потрібен ширший пул знайдених сторінок.

## Скільки коштує

Скрипт показує вартість кожного запиту і всього запуску за даними самого API. Приклад із 30 запитів у режимі `fast` коштував $0.05. Актуальні ціни: https://docs.perplexity.ai/getting-started/pricing

## Обмеження

- Скрипт працює через Perplexity Agent API. Відповіді в API і в застосунку perplexity.ai можуть відрізнятися: там інші моделі, персоналізація та історія розмови.
- Відповіді змінюються від запуску до запуску. Для висновків краще брати кілька десятків запитів, а не один.
- Прив'язка до країни м'яка: вона піднімає частку локальних джерел, але не прибирає інші.
- Код надається «як є». Питання й помилки можна писати в Issues, але без гарантії термінів.
